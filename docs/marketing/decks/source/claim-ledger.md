# AvalaOS external claim ledger

Deck codes: `M` Marketing, `C` Client, `I` Investor, `B` Internal Brand Board, `K` Messaging and Claim Book.

Status meanings:

- `IMPLEMENTED_AND_VERIFIED`: accepted source plus executed repository evidence for the bounded claim.
- `IMPLEMENTED_SOURCE_ONLY`: source exists but the wider acceptance or deployment boundary remains incomplete.
- `MARKETING_SAFE_CURRENT`: safe current positioning when the listed qualifier travels with the claim.
- `ROADMAP_ONLY`: future concept, visibly labelled.
- `REQUIRES_AP_INPUT`: cannot be represented as fact until AP supplies and approves the input.
- `EXTERNAL_RESEARCH_REQUIRED`: requires a later evidence-backed research pass.
- `PROHIBITED`: contradicted, unsafe, or unsupported.

## Source precedence and drift

- Current status authority is `docs/00_SOURCE_OF_TRUTH.md`, the active roadmap, task ledger, and readiness gates. Several older documents retain stale `PR 1D active` or `PR 1G not started` boilerplate.
- Canonical Studio PR #216 supports BRD, FRD, and PDD. Older product copy mentioning PRD/SDD is not used in external current-capability claims.
- Studio PR B is an implementation candidate, not accepted availability.
- `public/marketing/screenshots/application-portfolio-readiness.png` visibly shows a legacy V1 AP Invoice Decision Pack above the fold; it is not used as sole visual proof of the Application Portfolio workspace.
- Public copy mentioning private renditions is qualified because Studio PR B remains candidate-only.
- The Assess / Validate / Assemble / Launch / Audit lockup is current brand mnemonic equity, not proof of a current Assemble module.

## Delivery versus Monitor canonical copy

One governed handoff carries approved context into source-linked work items in Avala Delivery. Avala Monitor is a read-only visibility surface for disposition, readiness, risk, blockers, recorded outcomes, and lineage; it does not create work items.
