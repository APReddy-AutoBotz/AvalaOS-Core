# Governed multi-source Studio PR B migration and rollback

## Boundary

Migration `20260828120000_governed_multisource_studio_pr_b.sql` adds the server-authoritative Studio portion of the governed multi-source transcript and optional Assess-to-Studio handoff boundary. It does not change Assess scoring, KlarityFlow Health, provider secrets, deployment state, or Delivery PR C authority. `document_generations` remains legacy/unverified and is not backfilled into canonical Studio source packages.

The migration advances the repository migration-chain identity to `20260828120000`. That row is a repository convergence marker only; it is not evidence that a hosted environment applied the migration and does not authorize deployment.

## Migration behavior

- The first executable block preflights every existing canonical Studio artifact against its exact accepted PR 1E handoff, case version, review resolution, Govern resolution, and package hash. Any missing, dirty, or mismatched ancestry raises `STUDIO_PR_B_BACKFILL_REVIEW_REQUIRED` before the first mutation. The migration transaction then rolls back atomically.
- Every valid existing `studio_artifact_aggregate` receives exactly one deterministic `assess_handoff` source package. Aggregate/version IDs, versions, current and approved heads, approvals, content hashes, renditions, private-artifact links, and Assess ancestry are retained.
- Studio source sets and input bundles use the same server execution boundary as Assess while retaining exact `owner_module` separation. Existing Assess flags and behavior are unchanged. The capability-scoped Studio module projection includes a bounded inventory of same-tenant parsed immutable source-version IDs with safe labels, type, character count, and timestamp only. Its bundle rows carry the exact current bundle version/hash and source-set ID/version/hash selectors. Raw text, filenames, content/extraction hashes, buckets, and storage paths are not projected.
- `studio_multisource_enabled`, `studio_tenant_templates_enabled`, `module_handoffs_enabled`, and `direct_studio_planning_enabled` default to `false`.
- Direct, hybrid, and manual source packages are immutable exclusive unions. Direct/manual records are `not_assessed` and `planning_only`; optional Assess handoffs use a database-owned route-policy snapshot and one-time atomic consumption. Assess-to-Studio route policy v1 fixes expiry at seven days (604800 seconds) from request. Review, approval, and first consumption after expiry fail with `HANDOFF_EXPIRED` transactionally and cannot create an artifact.
- Every Studio transcript bundle is resolved to a server-owned candidate manifest containing only exact candidate/version/provenance/anchor/source/source-version/extraction-job/field/locator identities. Each selected source must have a human-accepted, reviewed candidate from the extraction job bound to that exact immutable bundle version. Edited candidates, merely suggested candidates, accepted candidates from another job, and same-source candidates bound to another bundle fail closed. The manifest hash and count are immutable source-package, handoff, generation-plan, and generation-attempt causality.
- Each source package and handoff also persists an immutable canonical anchor manifest. Each entry is exactly `{sourceVersionId, locator, anchorHash}`. Assess ancestry contributes `{sourceVersionId, "assess:accepted-handoff", upstreamPackageHash}`; transcript entries come from the exact accepted-candidate manifest. The manifest hash/count are copied into every generation plan and attempt. Provider output and human revisions must use an exact tuple from that manifest; a well-formed but different source version, locator, or hash is rejected by both Edge validation and the database trigger. Safe display labels and source-version display numbers are separate projection data and are never revision authority.
- Assess eligibility, handoff request, and consumption check the actual accepted upstream history for the same Assess case. A newer source-case version or later accepted handoff makes the older upstream obsolete; it is removed from eligibility and an already-approved target handoff becomes `stale` instead of creating a Studio artifact. Opaque decision-version labels are preserved as identity, not treated as lexically ordered authority.
- Consumption locks the target handoff, then the exact `assess_v2_cases` row, reloads the upstream handoff, and rechecks currentness before any Studio artifact/package/consumption write. Governed Assess handoff creation already serializes on that same case row and does not later acquire a Studio target-handoff lock, so this order has no inverse edge.
- `studio_pr_b_source_package_is_current(...)` is the single currentness decision for all four exclusive modes: exact current Assess head/latest accepted handoff, exact current locked Studio bundle, both hybrid halves, or exact private manual-brief material/hash. Artifact-v2 and workspace-v2 projections use it directly. Generation request, claim, final provider reservation, and finalization use the paired locking helper, acquiring the exact Assess case before the Studio bundle aggregate/version or manual material and before any reservation. A stale new request creates no generation receipt or attempt; a request-to-claim or claim-to-reservation race creates no new provider-effect reservation or effect. If either hybrid source half advances after provider authorization, finalization retains one immutable `stale_completed` result and leaves current and approved heads unchanged. Exact terminal replay returns that one result without a second version or effect.
- Manual source creation accepts bounded raw `manualBrief` only from the browser's source-package creation command at the service-owned transaction boundary, derives SHA-256 over its UTF-8 bytes, and stores the material in a private forced-RLS relation. Actor-scoped `studio.source-package.create` receipts provide exact replay and reject changed bindings with `IDEMPOTENCY_CONFLICT`. A later authorized generation command contains only durable package/version selectors; its service-only handler retrieves the committed private brief and sends it through the governed provider as framed untrusted input. No authenticated source-package, artifact, workspace, generation-plan, attempt, receipt, or audit projection returns the raw brief.
- Tenant template versions bind exact safe structure, review, independent approval, deprecation/replacement state, and immutable hashes. Provider endpoints, tools, headers, secrets, provider routing, prompts, and system-instruction authority are prohibited in tenant template structure.
- The safe template projection is one exact union for system and tenant templates. It returns ownership, exact template/version identity, safe display metadata, hash, renderer/content compatibility, normalized section definitions, replacement identity, and server-derived actions. System versions retain their canonical string identifiers; tenant versions and replacement versions are positive integers. Raw system `provider_instructions` are never projected.
- The safe handoff projection returns eligible accepted upstream PR 1E handoffs separately from requested handoffs. Requested rows carry the exact current immutable handoff-version ID, upstream ID, requestor-relative inbox/outbox direction, normalized reviewer-ready/approval-ready/approved/expired lifecycle, version, safe labels/timestamps, expiry, and server-derived actions. It never exposes the upstream package/body/hash or route-policy body.
- `studio_artifact_projection_v2(uuid, uuid, uuid)` is the capability-scoped `studio-artifact-2` projection. It leaves the accepted legacy `studio_artifact_projection` signature and shape unchanged. The v2 ancestry is a truthful discriminated union: assessed/mixed artifacts retain every exact Assess ancestry ID, while direct/manual artifacts carry explicit null Assess fields plus exact organization/workspace, source-package mode/ID/version/hash, schema/rule versions, optional Studio bundle selectors, and planning-only classification. The projection binds exact current version, source coverage/staleness, system-or-tenant template ID/version/hash/actions, and canonical sections shaped exactly as `{id,title,body,sourceAnchors,labels}`; it contains no raw manual material, provider instructions, or private source locator. New generation and human revision content must preserve exact selected-source coverage, allowed labels, and selected-source anchors; provenance loss, duplicate coverage, unselected anchors, and bundle anchor hashes absent from the immutable candidate manifest are rejected. Accepted legacy Assess-derived content remains readable.
- `studio_artifact_workspace_projection_v2(uuid, uuid, uuid, integer, integer)` is the tenant/workspace/capability-bound production workspace read. It returns the current artifact/version/sections, exact source-package ID/version/hash/mode, input-bundle ID/version, a bounded page of exact selected sources with total/page metadata, actual coverage/citations/uncovered sources/conflicts, safe provider availability, and server-derived actions. It returns `null` without `studio.artifacts.read`, preserves default-off behavior, and does not expose raw source/candidate/manual material, provider configuration identities, secrets, or private locators.
- Historical artifact/workspace projections retain safe display metadata for an immutable package source even if that source is later soft-deleted. Source inventory and source-set creation continue to exclude/reject soft-deleted sources, so deletion blocks new selection without erasing historical provenance. Hybrid source projection uses deterministic `DISTINCT ON (source_version_id)` ordering so Assess/transcript overlap appears once while canonical anchors remain exact tuples.
- `studio_artifact_summary_projection_v2(uuid, uuid, integer, integer)` is the authenticated reload/discovery selector gated by `studio.artifacts.read`. It returns `studio-artifact-summary-2` with `{items,total,offset,limit,hasMore}`. Each item contains only `{id,artifactType,aggregateVersion,lifecycle,currentVersionId,currentApprovedVersionId,sourceMode,lineageClassification,planningOnly,displayLabel,updatedAt,actions}`; page size is 1–50 and cross-tenant or unauthorized requests return `null`.
- `studio_artifact_source_package_projection(uuid, uuid, uuid)` is the pre-generation selector projection. It returns exact tenant-bound `artifactId`, `aggregateVersion`, nullable `currentVersionId`, nullable `currentApprovedVersionId`, `sourcePackageId`, `sourcePackageVersion`, `sourcePackageHash`, source mode/lineage/planning flags, safe source-presence booleans, route-policy version, and creation timestamp. The existing `version` package-version alias remains for caller compatibility. It returns `null` without `studio.artifacts.read` or on organization/workspace mismatch, and never returns raw manual material, provider data, or private source locations.
- Generation requests bind the exact source-package ID/hash, system or approved tenant-template ID/version/hash, expected aggregate/current/approved heads, server-selected provider route/config/model, prompt version, immutable provider-effect key, receipt, actor authorization version, and timeout.
- Studio generation reserves, settles, marks uncertain, or releases capacity through the canonical `enterprise_ai_budget_reservations` ledger. Its additive exclusive identity union stores the exact Studio command receipt and exact fenced generation attempt while existing Enterprise receipt/job rows retain their original checks and RPC behavior. Studio reservation requires current `studio.artifacts.generate` authority, the unified gateway flag, current route/config/model/fence identity, and the same workspace budgets; no browser or provider response can mint budget authority.
- Reservation and lease recovery use one lock graph. Reserve takes scoped budget advisory lock → workspace flags → Studio receipt → generation attempt → route/config → reservation; claim and settle/uncertain/release take generation attempt → reservation and never acquire advisory, receipt, route, or config locks afterwards. An expired lease with a reserved, uncertain, settled, or released-after-reconciliation reservation is reconciliation-only and cannot authorize a second provider effect. Only a reservation explicitly released with `before_provider_effect` may transfer atomically to a new token/fence; one persisted `studio_transfer_pending` bit grants the new worker exactly one provider-effect ownership response and is then cleared.
- Response-loss recovery retains one provider-effect key. Unstaged lease retry can replay the unified gateway effect; a staged response is atomically re-fenced for reconciliation without changing response content/hash. Finalization revalidates heads, package, cancellation state, and current template approval/supersession. Late results are retained only as stale versions and never move current or approved heads.
- `studio_artifact_generation_fail_v2(uuid, uuid, bigint, text)` is the only PR B terminal provider-failure write. Its first terminal transition requires the exact current execution token and fence, an unexpired lease, state exactly `generating`, a null response hash, and no staged response. `response_staged`, `reconciling`, and `cancel_requested` remain recovery/cancellation-owned and fail with `VERSION_CONFLICT` without mutation; a stale or expired worker receives `STALE_EXECUTION_FENCE` before any state, audit, or recovery mutation. Exact terminal replay returns the stored failure deterministically. The function retains the bounded Studio provider/governance/output/model/usage/coverage/start/completion failure taxonomy, sanitizes unknown codes to `GENERATION_FAILED`, and rejects `GENERATION_UNCERTAIN` because an uncertain provider effect remains reconciliation-owned and must not release active ownership. Its audit and recovery rows contain only the attempt/artifact/fence/normalized-code terminal binding, never raw provider responses, source content, manual material, or private locators.
- A temporary database guard rejects Studio-to-Delivery mutation for any package mode other than `assess_handoff` with `STUDIO_PR_B_DELIVERY_PATH_DISABLED`.

The exact named failure RPC arguments are `{p_attempt_id, p_execution_token, p_fence, p_failure_code}`. Supabase/PostgREST callers must use those names; `p_fence` is the current claim's exact positive execution fence.

## Rollback and read-only fallback

Do not destructively reverse the migration or delete durable source, template, handoff, generation, audit, approval, or recovery history.

1. Set all four PR B workspace flags to `false` for affected workspaces.
2. Set `studio_artifact_runtime_control.read_only=true` and `provider_enabled=false` to disable Studio mutation/provider execution while retaining safe reads.
   Do not fall back to the legacy unfenced `studio_artifact_generation_fail`; leave active attempts for fenced reconciliation, cancellation, or timeout.
   Preserve `stale_completed` results and their exact source-package ancestry read-only; do not promote them, rewrite heads, or delete them during rollback.
3. Keep the temporary Delivery guard active. Do not enable direct/hybrid/manual Delivery before an approved PR C migration replaces it.
4. Revoke execute on the four Studio budget RPCs if provider execution must be isolated; do not alter or delete canonical Enterprise or Studio budget reservations.
5. Preserve the accepted Assess-derived legacy generation path for deterministic `migrationBackfill`/legacy Assess packages only.
6. Correct defects with an additive forward migration. If ancestry preflight fails, leave the migration unapplied and route the stable review-required code for human reconciliation.
